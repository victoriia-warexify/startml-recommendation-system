# Рекомендательная система постов: HGB, MLP и A/B-анализ

Учебный проект по машинному обучению и аналитике данных. Задача — предсказать вероятность положительного отклика пользователя на пост, ранжировать кандидатов и сравнить два алгоритма рекомендаций.

В проекте есть подготовка признаков, обучение моделей, FastAPI-сервис и отдельный анализ A/B-эксперимента на логах, предоставленных курсом **Start ML**.

## Что реализовано

- **Подготовка данных:** PostgreSQL, pandas, обработка пользовательских и текстовых признаков.
- **32 признака:** контекст запроса, параметры пользователя, популярность постов, история взаимодействий и предпочтения по темам/текстовым кластерам.
- **Защита от временной утечки:** исторические признаки для обучения формируются только из событий, доступных к моменту соответствующего просмотра. Для теста и API используется фиксированный срез истории на `2021-12-12`.
- **Две модели:** `HistGradientBoostingClassifier` (**Control**) и `MLPClassifier` (**Test**) со `scikit-learn` и отдельной предобработкой категориальных признаков.
- **API:** выдаёт рекомендации и детерминированно относит пользователя к одной из двух групп по хешу `user_id`.
- **Оценка:** ROC-AUC, Average Precision и дополнительный offline-анализ Observed HitRate@5 по уникальным постам.
- **Эксперименты:** абляция признаков и дополнительные варианты MLP с `SentenceTransformer`-эмбеддингами и семантическим профилем пользователя.
- **Тесты:** `pytest`, в том числе проверки признаков, моделей, API и выгрузки данных.

## Результаты A/B-анализа

В `ab_test.ipynb` разобраны **отдельные учебные логи A/B-эксперимента**, предоставленные курсом. Пользователи, попавшие в обе группы (4 человека), исключены.

| Метрика | Control | Test |
| --- | ---: | ---: |
| Уникальные пользователи | 32 350 | 32 659 |
| Доля пользователей хотя бы с одним лайком | 89,13% | 89,82% |
| Среднее число лайков на пользователя | 3,49 | 3,59 |
| Медианное число лайков | 3 | 3 |
| Доля выдач с сопоставленным лайком | 70,67% | 71,98% |

- Баланс групп: биномиальный тест, `p = 0,227` — значимого отклонения от 50/50 не выявлено.
- Доля пользователей с лайком: `+0,68` п. п. в Test, χ²-тест, `p = 0,00445`.
- Число лайков: критерий Манна — Уитни, `p ≈ 2,96 × 10⁻⁵`.
- Доля выдач с лайком: `+1,32` п. п. в Test, t-тест Уэлча по **100 бакетам** в каждой группе, `p ≈ 8,09 × 10⁻⁸`.

При уровне значимости `0,05` различия в этих метриках статистически значимы. Поскольку общего идентификатора выдачи и лайка нет, сопоставление выполнено по пользователю, времени (окно до 1 часа) и рекомендованному посту. **Это приближённая доля выдач с лайком, не точный CTR.** Учебные A/B-логи не подтверждены как данные работы именно текущих HGB/MLP — переносить этот эффект на обученные в проекте модели нельзя.

## Запуск

Тестировалось на Python 3.13. Для локальной работы нужна доступная база PostgreSQL с исходными таблицами `public.user_data`, `public.post_text_df`, `public.feed_data`; для API дополнительно нужны сохранённые таблицы признаков и совместимые файлы моделей.

**1. Создать окружение и установить зависимости:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для дополнительных семантических экспериментов (скачивание моделей Transformer может занять время и место на диске):

```bash
python -m pip install -r requirements-semantic.txt
```

**2. Настроить подключение:**

```bash
cp .env.example .env
```

Заполнить `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`. Файл `.env` находится в корне проекта и **не публикуется**. Для подготовленных 5%-ных таблиц используется `FEATURE_TABLE_PREFIX=recsys_5pct`.

**3. Проверить проект без обращения к настоящей базе:**

```bash
python -m pytest -q
```

В последней локальной проверке прошло **99 тестов**. Два предупреждения зависимостей Starlette/AnyIO не влияли на прохождение тестов.

**4. Запустить API (если есть подготовленные таблицы и модели):**

Поместить совместимые `model_control.pkl` и `model_test.pkl` в каталог, указанный через `MODELS_DIR` (например, `models_5pct`). Затем:

```bash
uvicorn app:app --reload
```

Пример запроса после запуска (пользователь должен существовать в базе, дата — позже исторического среза):

```text
GET http://127.0.0.1:8000/post/recommendations/?user_id=200&dt=2021-12-20T12:00:00&limit=5
```

Ответ содержит поле `exp_group` (`control` / `test`) и список рекомендованных постов с `id`, `text` и `topic`. Swagger-документация API: <http://127.0.0.1:8000/docs>.

**5. Воспроизвести основные эксперименты (необязательно):**

```bash
python model_control.py --train --output-model models_5pct/model_control.pkl
python model_test.py --train --output-model models_5pct/model_test.pkl
python evaluate_observed_hitrate.py --control models_5pct/model_control.pkl --test models_5pct/model_test.pkl
```

Обучение **не требуется** для запуска тестов. Скрипты обучения не перезаписывают существующие файлы моделей без явного разрешения. Экспорт в PostgreSQL производится отдельно через `save_features.py` и требует флага `--allow-db-write` и нового префикса таблиц: на уже существующие таблицы он не рассчитан.

Для ноутбука `ab_test.ipynb` положить полученные на курсе `views.csv` и `likes.csv` рядом с ним и выполнить ячейки сверху вниз. CSV не входят в репозиторий.

## Ограничения

- База данных и обученные модели не входят в репозиторий: API нельзя запустить «из коробки» без этих ресурсов.
- Offline Observed HitRate@5 оценивает ранжирование на исторических просмотренных постах и не равнозначен онлайн-CTR; результаты для уникальных постов следует пересчитать на своих сохранённых моделях перед публикацией окончательных цифр.
- История признаков в API фиксируется на дату среза; живое дообучение и обновление истории в проекте не реализованы.
- Семантические модели — отдельные эксперименты, не подключённые к основному API.
- Данные предоставлены курсом для учебной работы; исходные таблицы и логи эксперимента в GitHub не выкладываются.
