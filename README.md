# Рекомендательная система постов — HGB, MLP и A/B-анализ

Учебный проект по машинному обучению и аналитике данных в рамках курса **Start ML от [karpov.courses](https://karpov.courses/ml-start)**.

**Задача:** оценивать вероятность положительной реакции пользователя на пост, ранжировать кандидатов и возвращать рекомендации через API. В проекте реализованы два алгоритма, построение исторических признаков без использования будущих событий, оценка моделей и анализ отдельного учебного A/B-эксперимента.

## Основные результаты

### Offline-сравнение моделей

Для обучения используется около **5% пользователей** (отбор `user_id % 20 == 0`). Временная граница Train/Test — **12 декабря 2021 года**: обучение на событиях до этой даты включительно, оценка на более поздних событиях.

| Модель | Test ROC-AUC | Test Average Precision |
| --- | ---: | ---: |
| HistGradientBoostingClassifier (Control) | ≈ 0,686 | ≈ 0,232 |
| MLPClassifier (Test) | ≈ 0,691 | ≈ 0,233 |

*Здесь приведены округлённые результаты предыдущих запусков обучения. Для их независимого воспроизведения необходимы исходные таблицы PostgreSQL, не включённые в репозиторий.*

MLP показала небольшое преимущество по обеим метрикам. Разница невелика, поэтому сами по себе offline-метрики не доказывают улучшение пользовательского опыта при онлайн-эксперименте.

Дополнительно реализована диагностика **Observed HitRate@5** на исторических просмотренных постах: один `post_id` учитывается один раз на пользователя, а в качестве целевой метки используется результат первого просмотра. Эта метрика не является оценкой настоящего онлайн-HitRate, поскольку кандидаты формируются из наблюдавшихся событий. Окончательные значения для уникальных постов в README не приводятся до повторного расчёта на сохранённых моделях.

### Анализ учебного A/B-эксперимента

В [`ab_test.ipynb`](ab_test.ipynb) исследуются **отдельные логи эксперимента, предоставленные курсом**: выдачи рекомендаций и события лайков. Эти логи не подтверждены как результаты работы именно обученных выше HGB и MLP, поэтому выводы A/B-анализа нельзя переносить на них напрямую.

После исключения четырёх пользователей, попавших одновременно в обе группы:

| Метрика | Control | Test |
| --- | ---: | ---: |
| Число пользователей | 32 350 | 32 659 |
| Доля пользователей хотя бы с одним лайком | 89,13% | 89,82% |
| Среднее число лайков на пользователя | 3,49 | 3,59 |
| Медиана лайков | 3 | 3 |
| Доля выдач с сопоставленным лайком | 70,67% | 71,98% |

Проверки при уровне значимости **α = 0,05**:

- **Баланс групп:** биномиальный тест, `p = 0,227`. Значимого отклонения от распределения 50/50 не обнаружено.
- **Доля пользователей с лайком:** χ²-тест для двух долей, разница Test − Control — **+0,68 п. п.**, `p ≈ 0,00445`.
- **Число лайков на пользователя:** критерий Манна — Уитни, `p ≈ 2,96 × 10⁻⁵`. Среднее в Test выше примерно на **0,11 лайка**, медиана одинакова.
- **Доля выдач с лайком:** разница Test − Control — **+1,32 п. п.**, `p ≈ 8,09 × 10⁻⁸` по двустороннему t-тесту Уэлча на **100 бакетах в каждой группе**.

В учебных данных обнаружены статистически значимые различия в пользу Test по рассмотренным метрикам. **Доля выдач с сопоставленным лайком — приближённая метрика, не точный CTR:** общего идентификатора выдачи и лайка нет, поэтому сопоставление восстановлено по пользователю, посту и временному окну до одного часа. В одном из вариантов сопоставления лайк приписывается последней подходящей выдаче.

## Что реализовано

- **Подготовка данных:** загрузка пользовательских, текстовых и событийных данных из PostgreSQL; преобразования в `pandas`.
- **32 признака:** характеристики пользователя, поста и времени, статистика взаимодействий, предпочтения по темам и текстовым кластерам.
- **Временная корректность:** признаки обучающих событий используют только ранее произошедшие взаимодействия; для Test и API исторические признаки фиксируются на срезе `2021-12-12`.
- **Предобработка:** One-Hot Encoding категорий, частотное кодирование городов, масштабирование и логарифмирование отдельных числовых признаков.
- **Модели:** `HistGradientBoostingClassifier` и `MLPClassifier`; количество эпох MLP выбирается на отдельной временной Validation (28 ноября — 12 декабря 2021 года), без использования независимого Test.
- **API:** сервис на FastAPI с детерминированным распределением пользователей в группы Control/Test, ранжированием постов и исключением ранее просмотренных постов из сохранённой истории.
- **Дополнительные эксперименты:** абляция наборов признаков, семантические признаки на основе `SentenceTransformer`, персонализированные векторы интересов пользователей.
- **Проверки:** тесты `pytest` для признаков, моделей, API, метрик и экспорта таблиц.

## Установка и запуск

Проект проверялся на **Python 3.13**. Для воспроизведения обучения необходим PostgreSQL с таблицами `public.user_data`, `public.post_text_df`, `public.feed_data`. Для API дополнительно нужны сохранённые таблицы признаков и совместимые файлы обученных моделей.

### 1. Установить зависимости

```bash
git clone https://github.com/victoriia-warexify/startml-recommendation-system.git
cd startml-recommendation-system
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для отдельных семантических экспериментов:

```bash
python -m pip install -r requirements-semantic.txt
```

### 2. Настроить окружение

Создать в корне проекта файл `.env` с собственными параметрами подключения:

```dotenv
PGHOST=localhost
PGPORT=5432
PGDATABASE=your_database
PGUSER=your_user
PGPASSWORD=your_password
FEATURE_TABLE_PREFIX=recsys_5pct
MODELS_DIR=models_5pct
```

Это пример, а не действующие реквизиты. `.env` исключён из Git через `.gitignore`. `FEATURE_TABLE_PREFIX` должен соответствовать названиям уже подготовленных таблиц признаков в базе.

### 3. Запустить тесты

```bash
python -m pytest -q
```

Последняя локальная проверка: **99 passed**. Для этих тестов не требуется реальное подключение к PostgreSQL или обучение моделей.

### 4. Обучить модели (при наличии исходных данных)

```bash
python model_control.py --train --output-model models_5pct/model_control.pkl
python model_test.py --train --output-model models_5pct/model_test.pkl
```

Существующие файлы моделей не перезаписываются без флага `--overwrite-model`. Для работы API нужны **совместимые таблицы признаков того же исторического среза**. Их экспорт отдельно выполняет `save_features.py`; запись в базу требует явного флага `--allow-db-write` и нового префикса таблиц. Без необходимости повторно экспортировать данные не следует.

### 5. Запустить API

При наличии моделей в `MODELS_DIR` и необходимых таблиц PostgreSQL:

```bash
uvicorn app:app --reload
```

Пример запроса:

```http
GET /post/recommendations/?user_id=200&dt=2021-12-20T12:00:00&limit=5
```

Пример структуры ответа:

```json
{
  "exp_group": "control",
  "recommendations": [
    {"id": 123, "text": "Текст поста", "topic": "news"}
  ]
}
```

*Здесь приведена структура JSON, а не реальный результат работы модели.* Конкретная группа пользователя и список постов определяются при выполнении запроса. Документация API после запуска: `http://127.0.0.1:8000/docs`.

### 6. Открыть A/B-ноутбук

Для воспроизведения анализа нужны предоставленные курсом файлы `views.csv` и `likes.csv`, размещённые в корне проекта. После этого открыть `ab_test.ipynb` и выполнить ячейки по порядку. Исходные CSV не опубликованы в репозитории.

## Ограничения проекта

- Исходные данные, подготовленные таблицы PostgreSQL и файлы `.pkl` не включены в GitHub. Поэтому **полное обучение и запуск API не воспроизводятся из одного только репозитория**.
- Исторический срез для API фиксирован; обновление признаков в реальном времени и онлайн-дообучение не реализованы.
- Offline Observed HitRate@5 рассчитывается по просмотренным в истории постам и не заменяет оценку онлайн-качества рекомендаций.
- Дополнительные семантические модели существуют как исследовательские эксперименты и не подключены к основному API.
- Статистические результаты A/B-ноутбука относятся к отдельным логам учебного эксперимента, а не к проверенному онлайн-развёртыванию текущих моделей.
